# Agent Harnesses

Open-Inspect keeps its existing browser-to-control-plane WebSocket protocol and selects the coding
agent implementation inside each sandbox. The sandbox bridge is the provider boundary: it adapts
OpenCode, Codex app-server, Claude Agent SDK, and CodeWhale/DeepSeek events into the same session
event stream. This keeps the Web client, Slack, Feishu, GitHub, and Linear integrations independent
of a particular harness protocol.

## Configure Harnesses

Open **Settings > Harnesses** to:

- enable or disable the four installed harnesses;
- choose the deployment default used when a session, Environment, or Automation does not override
  it;
- inspect runtime and model-provider readiness;
- store deployment-wide Codex `auth.json`, a Codex enterprise access token, or a Claude Code
  `setup-token`;
- inspect and manage the Host-only DeepSeek provider credential when Host management is configured.

The page returns only configuration state, expiry metadata, and short SHA-256 fingerprints. It never
returns a stored credential value. Only a deployment administrator can mutate shared settings. Set
`deployment_admin_identities` to a comma-separated list such as
`github:octocat,email:admin@example.com`. If it is empty, exact `allowed_users` and `allowed_emails`
entries are administrators; broad organization, domain, and open admission rules never grant
administrator rights.

The dedicated credential editors are deployment-wide. Existing repository and Environment overrides
remain supported through their **Secrets** editors and participate in the normal target scope and
precedence rules.

## Credential Boundaries

| Credential                           | Storage and delivery                                                                                                                   |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| Codex `auth.json` / enterprise token | Encrypted D1 secret, materialized only in a live sandbox's memory-backed credential directory                                          |
| Claude Code `setup-token`            | Encrypted D1 secret, moved to a memory-backed file before the agent starts                                                             |
| DeepSeek provider key                | Host file with mode `0600`; never stored in D1, injected into a sandbox, or captured in an image/snapshot                              |
| `SANDBOX_AUTH_TOKEN`                 | Per-session internal credential generated by the control plane; intentionally not user-configurable                                    |
| Host management HMAC secret          | Deployment bootstrap secret shared only by Cloudflare and the Host service manager; intentionally not user-configurable in the web app |

Native harness credentials are removed from image-build environments. Codex login files are removed
before snapshots, and the agent command environment is sanitized so tools do not inherit these
values.

## Runtime-Owned MCP and Browser Tools

Every native harness receives the local `open_inspect` MCP server. It owns platform actions such as
PR creation, media upload, and child-session coordination, keeping the sandbox capability out of
harness-generated shell commands. OpenCode receives equivalent runtime commands and server-side tool
integration.

The maintained Cube image additionally starts the runtime-owned `aio_browser` MCP at the exact
loopback URL recorded in `AIO_BROWSER_MCP_URL`. OpenCode, Codex, Claude Code, and DeepSeek receive
that reserved entry automatically. The URL validator accepts only loopback HTTP with the `/mcp`
path; a session-supplied MCP server cannot replace the built-in name.

`agent-browser` and `aio_browser` share the supervisor-owned Chromium CDP endpoint. Harness choice
therefore does not change browser state, screenshot behavior, or the authenticated media upload
path. See [ADR 0005](./adr/0005-cube-aio-browser-runtime.md).

## Host Model Relay

DeepSeek traffic uses the Host relay documented in
[`packages/e2b-infra/README.md`](../packages/e2b-infra/README.md). Configure:

```hcl
model_relay_public_url        = "https://models.example.com"
model_relay_admin_url         = "https://models-admin.example.com"
model_relay_admin_auth_secret = "a-long-random-bootstrap-secret"
```

The public URL is injected by the control plane into fresh and restored sandboxes and overrides any
user secret with the same relay variable name. The admin URL should be a restricted Cloudflare
Tunnel hostname or route. Control-plane requests are signed with the `sig1` service-auth format,
including the method, path, canonical query, body hash, timestamp, and one-time nonce. The Host
rejects expired, replayed, or modified requests.

When an administrator rotates a DeepSeek key, the Host validates the candidate against DeepSeek
first and then atomically replaces the file. A failed validation leaves the previous key active.

## Readiness and Preflight

The control plane combines four inputs:

1. the enabled Harness preference stored in D1;
2. `SANDBOX_RUNTIME_HARNESSES`, which must match the CLIs installed in the sandbox image;
3. the selected model provider and Harness compatibility;
4. effective deployment, Environment, or repository credentials and Host relay status.

The browser disables a Harness with no usable provider route and marks partial readiness in the
selector. The control plane independently rechecks session creation, Automation launches, child
sessions, and every queued prompt/model override. Failures return a stable readiness code such as
`CREDENTIAL_MISSING`, `CREDENTIAL_EXPIRED`, `MODEL_INCOMPATIBLE`, or `RELAY_UNAVAILABLE` before a
sandbox starts or a prompt is persisted.

Existing sessions remain pinned to the Harness selected at creation. Changing the deployment default
affects only new sessions.

## Sandbox Image Capability

The maintained Modal and self-hosted Cube/E2B images install the four pinned harness runtimes. If a
custom image omits one, remove it from `sandbox_runtime_harnesses`; the Settings page and server
preflight will report it as unavailable instead of attempting to launch it.
